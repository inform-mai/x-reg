# x-reg: первичные данные для заполнения БД

Пока только описание, в БД ничего не вносим.

## Порядок заполнения

Таблицы заполняются в порядке зависимостей по внешним ключам. Запись, на которую ссылаются, должна существовать раньше той, что ссылается.

1. `departments` — ни от чего не зависит
2. `employees` — ссылается на `departments`
3. `users` — ссылается на `employees` (необязательно)
4. `blacklist` — ссылается на `employees` и `users`
5. `reports` — ссылается на `users`
6. `report_items` — ссылается на `reports`

Поля `id` типа UUID (users, reports, report_items, blacklist) заполнять не нужно, они генерируются автоматически. Ниже для удобства используются условные обозначения вроде `<id пользователя admin>`.

## 3. User (`users`)

Пользователи — это те, кто работает в приложении (отдел кадров), а не все сотрудники.

| full_name | email | is_active | employee_id |
|---|---|---|---|
| Админ | `admin` | true | NULL |
| Смирнова Ольга Николаевна | o.smirnova@company.local | true | `o.smirnova` |
| Морозова Татьяна Павловна | t.morozova@company.local | false | `t.morozova` |

- Пользователь `admin` / «Админ» совпадает с `DEV_USER_EMAIL` и `DEV_USER_FULL_NAME` по умолчанию из `config.py`. Приложение и так создаёт его само при первом запросе (`get_or_create_dev_user`), поэтому вносить его можно и не вносить. Если внести, он просто найдётся по email.
- `email` уникален, повторяться не может.
- `employee_id` необязателен: у админа его нет, у сотрудниц отдела кадров это ссылка на их карточку.
- Неактивный пользователь (`t.morozova`) нужен для проверки поля `is_active`.

## 5. Report (`reports`) и 6. ReportItem (`report_items`)

В обычной работе эти таблицы заполняет само приложение: по кнопке «Сформировать отчёт» (`POST /api/v1/reports`) оно создаёт отчёт со строками и тут же меняет статусы сотрудников. Для первичного заполнения достаточно одного «исторического» отчёта, чтобы история выгрузок не была пустой.

| `<id отчёта выше>` | `d.sokolov` | grant | Соколов Дмитрий Андреевич | Backend-разработчик | +7 (999) 345-67-89 | d.sokolov@company.local | Отдел веб-разработки |

- `file_name` строится по тому же шаблону, что и в `services/reports.py`.
- Поля строки — копия данных сотрудника на момент отчёта, `department_title` берётся из названия отдела.

## Замечание для команды

В `models.py` значения по умолчанию для дат заданы как `default=utc_now()` (со скобками). Из-за этого функция вызывается один раз при запуске приложения, и все новые записи получают одно и то же время — время старта сервера. Правильно писать `default=utc_now` и `onupdate=utc_now`, без скобок: тогда функция вызывается при каждой вставке. Пока это не исправлено, даты в первичных данных лучше указывать явно.
